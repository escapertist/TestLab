# TestLab

FastAPI-сервис генерации тестов по учебным материалам: преподаватель загружает PDF, отдельным
запросом запускает генерацию, GigaChat составляет по тексту тест (5 закрытых + 2 открытых вопроса),
материал и тест сохраняются, клиент получает тест с вариантами ответов и рубриками.

## Что уже работает

- `POST /auth/register`, `POST /auth/login`, `GET /auth/me` — регистрация и вход (токен-заглушка:
  `id` пользователя вместо JWT).
- `POST /materials` — загрузка PDF: проверка типа, размера и текстового слоя, сохранение файла и
  материала. Тест при загрузке не создаётся, модель не вызывается.
- `POST /materials/{id}/tests` — создание теста по сохранённому файлу: текст → GigaChat → тест
  `draft` с 7 вопросами. Повторный вызов — `409`, сбой модели — `502` без теста.
- `GET /materials` — список своих материалов с пагинацией.
- `GET /materials/{id}` — карточка материала с тестом (`test: null`, пока тест не создан).
- `GET /materials/{id}/file` — скачивание исходного PDF.
- `DELETE /materials/{id}` — удаление материала, файла и связанных тестов.

Остальные эндпоинты тестов (CRUD, публикация), вопросов, назначений и проверки описаны в `docs/API.md`
как план.

## Запуск

```powershell
uv sync
testlab-init-db          # создаёт схему; --reset пересоздаёт
python -m testlab        # uvicorn на http://127.0.0.1:8000, документация на /docs
```

`.env` в корне нужен только для секретов и необязательных переопределений: он в `.gitignore` и
создаётся вручную. Все параметры (`DB_URL`, `UPLOADS_DIR`, `UPLOADS_MAX_BYTES`, `GIGACHAT_*`)
имеют безопасные дефолты в `src/testlab/config/` — без `.env` сервис запускается.

`GIGACHAT_CREDENTIALS` (`client_id:secret` в base64) обязателен для генерации: без него
`POST /materials/{id}/tests` вернёт `502`. Загрузке, списку, карточке и скачиванию он не нужен.

## Архитектура

Четыре слоя и явные границы: `routers → services → repositories → models`, плюс `schemas`
(Pydantic-контракты), `infrastructure` (PDF и файловое хранилище), `llm` (транспорт GigaChat,
промпт и правила разбора ответа — единственный каталог, названный по теме), `dependencies` (сборка
зависимостей). Перечисления живут в `models/enums.py`: это типы колонок БД. Одна транзакция на use
case через `UnitOfWork`, доменные ошибки маппятся в HTTP централизованно, правила зависимостей между
слоями закреплены тестом `tests/test_imports.py`. Подробности — в `AGENTS.md`.
