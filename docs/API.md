# API TestLab

Документ описывает REST API сервиса генерации и проверки тестов: что принимаем, что отдаём, кому можно.

## Общие принципы

- Формат: JSON (`Content-Type: application/json`), кроме загрузки файлов — `multipart/form-data`.
- Время: ISO 8601 в UTC, например `2026-11-24T10:15:30Z`.
- Изображения/файлы: пока не реализовано, эндпоинты помечены как «этап 3».
- Базовый префикс не версионирован. Если понадобится — `app.include_router(..., prefix="/api/v1")` в `__main__.py`, эндпоинты не меняются.

## Роли

| Роль | Что может |
|---|---|
| `student` | видеть свои назначения, проходить тест, смотреть свои результаты |
| `teacher` | загружать материалы, создавать тесты и вопросы, назначать их студентам, проверять открытые ответы |

Роль выбирается пользователем при регистрации (временно, для учебного проекта). Роли `admin` в проекте нет.

## Авторизация

**Сейчас**: заглушка вместо JWT. `POST /auth/login` возвращает `access_token`, равный `id` пользователя. Заголовок `Authorization: Bearer <access_token>` проверяется зависимостью `get_current_user`: она ищет пользователя по этому `id` и отдаёт `401`, если его нет.

**План**: подписать токен (JWT) и проверять срок действия. Пока эндпоинты делят доступ по роли через `get_current_user` и `get_current_teacher`.

Все эндпоинты ниже, кроме `/auth/register` и `/auth/login`, требуют заголовок `Authorization: Bearer <access_token>`.

## Коды ответов

| Код | Когда |
|---|---|
| `200` | успех |
| `201` | создан объект (регистрация, материал, тест, вопрос, назначения, попытка) |
| `204` | удалено (без тела) |
| `400` | бизнес-ошибка: username занят, не PDF, в PDF нет текста, тест уже опубликован, попытка завершена |
| `401` | нет/неверный токен, неверный логин или пароль |
| `403` | роль не позволяет, чужой объект |
| `404` | объект не найден или не виден этому пользователю |
| `409` | конфликт: тест для материала уже создан, дубль назначения, ответ уже отправлен |
| `413` | файл больше `UPLOADS_MAX_BYTES` |
| `422` | невалидное тело запроса (стандарт FastAPI) |
| `500` | ошибка сохранения (транзакция откатывается) |
| `502` | GigaChat недоступен или нарушил контракт ответа |

Формат ошибки — стандартный FastAPI:

```json
{"detail": "Пользователь с таким username уже существует"}
```

## 3. Материалы (teacher) — реализовано

Учебный материал — файл, из которого генерируется тест. Все операции доступны только роли
`teacher` и только для своих материалов: чужой материал неотличим от отсутствующего (`404`).

| Метод | Путь | Что делает | Код успеха |
|---|---|---|---|
| `POST` | `/materials` | загрузить PDF + `title`, сохранить материал и файл (без генерации) | `201` |
| `GET` | `/materials?limit=&offset=` | список своих материалов | `200` |
| `GET` | `/materials/{material_id}` | карточка материала с тестом | `200` |
| `GET` | `/materials/{material_id}/file` | скачать файл (`FileResponse`) | `200` |
| `DELETE` | `/materials/{material_id}` | удалить материал, файл и связанные тесты | `204` |

Тест при загрузке не создаётся: это отдельное действие `POST /materials/{material_id}/tests`
(раздел 4). После загрузки карточка отдаёт `test: null`, пока тест не создан.

`POST /materials` — `multipart/form-data`: поля `file` (PDF, до `UPLOADS_MAX_BYTES`, по умолчанию
10 МБ) и `title` (1–255 символов). Запрос проверяет расширение и `Content-Type` файла, его размер и
наличие текстового слоя (PDF разбирается `pypdf` только как проверка), затем сохраняет файл и запись
материала. `201`:

```json
{
  "id": "...",
  "title": "Лекция 3. Базы данных",
  "filename": "lecture3.pdf",
  "is_uploaded": true,
  "created_at": "2026-11-24T10:15:30Z"
}
```

Ошибки загрузки: `400` — не PDF, пустой файл, в PDF нет текстового слоя; `401` — нет или неверен
токен; `403` — роль не `teacher`; `413` — файл больше лимита; `500` — сбой сохранения (файл при
этом удаляется). Сбоев модели загрузка не порождает: она её не вызывает.

`teacher_id` берётся из токена, а не из тела.

`GET /materials` отдаёт `{"items": [Material, ...], "total": N}`; материалы отсортированы по
`created_at` по убыванию, `limit` — 1..100 (по умолчанию 20), `offset` — не меньше 0, иначе `422`.

```json
{
  "items": [
    {"id": "...", "title": "Лекция 3", "filename": "lecture3.pdf", "is_uploaded": true, "created_at": "2026-11-24T10:15:30Z"}
  ],
  "total": 1
}
```

`GET /materials/{material_id}` возвращает те же поля плюс `test` (тот же объект, что в разделе 4, или
`null`, пока тест не создан). `GET /materials/{material_id}/file` отдаёт
`application/pdf` с исходным именем файла в `Content-Disposition`; `404`, если файла нет на диске.
Серверный путь к файлу (`file_path`) не отдаётся ни в одном ответе.

## 4. Тесты (teacher)

### `POST /materials/{material_id}/tests` — реализовано

Отдельное действие «создать тест по материалу»: читает сохранённый файл материала, извлекает текст,
вызывает GigaChat и сохраняет тест в статусе `draft`. Состав задаётся телом запроса: `closed_count`
(по умолчанию 5), `open_count` (по умолчанию 2) и `options_count` (по умолчанию 4, от 2 до 10); сумма
`closed_count + open_count` — от 1 до 20. Тело запроса необязательно; если передан `title` (1–255), он
используется как название теста, иначе название берётся из ответа модели.

```json
{"title": "Итоговый тест по лекции 3", "closed_count": 5, "open_count": 2, "options_count": 4}
```

`201` — тест с вопросами и вариантами:

```json
{
  "id": "...",
  "material_id": "...",
  "title": "Итоговый тест по лекции 3",
  "status": "draft",
  "generation_params": {"model": "GigaChat-3-Ultra", "closed_count": 5, "open_count": 2, "options_count": 4, "text_chars": 18420, "text_truncated": false},
  "created_at": "2026-11-24T10:15:30Z",
  "questions": [
    {"id": "...", "type": "closed", "text": "...", "points": 1, "order_index": 1, "reference_answer": null,
     "options": [{"id": "...", "text": "...", "is_correct": true, "order_index": 1}]},
    {"id": "...", "type": "open", "text": "...", "points": 3, "order_index": 2,
     "reference_answer": "..."}
  ]
}
```

Ошибки: `400` — в PDF нет текстового слоя; `401` — нет или неверен токен; `403` — роль не `teacher`;
`404` — материал не найден, принадлежит другому преподавателю или файла нет на диске; `409` — у
материала уже есть тест (второй не создаётся, актуальный тест берётся из карточки); `422` — состав
вне допустимого диапазона; `500` — сбой
сохранения теста (материал остаётся загруженным); `502` — GigaChat недоступен или вернул ответ,
не совпадающий с запрошенным составом (тест и вопросы не сохраняются, материал и файл остаются доступны).

`generation_params` хранится как JSON-строка в SQLite и отдаётся как JSON-объект. Для генерации нужен
`GIGACHAT_CREDENTIALS` в `.env` (`client_id:secret` в base64): без него действие вернёт `502`.

### Остальные операции с тестами — не реализовано (план)

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/tests?material_id=&status=&limit=&offset=` | список своих тестов |
| `GET` | `/tests/{test_id}` | тест с вопросами |
| `PATCH` | `/tests/{test_id}` | изменить `title`, `generation_params` (только `draft`) |
| `POST` | `/tests/{test_id}/publish` | `draft` → `published` |
| `POST` | `/tests/{test_id}/archive` | `published` → `archived` |
| `DELETE` | `/tests/{test_id}` | удалить тест (только `draft`) |
| `POST` | `/tests/{test_id}/generate` | этап 3: сгенерировать вопросы через LLM |

`POST /tests/{test_id}/publish` — `200`, тело теста; `400`, если вопросов нет. После публикации вопросы менять нельзя (`409`), иначе у уже назначенных тестов поедут версии.

`POST /tests/{test_id}/generate` — `202`:

```json
{"status": "started", "generated": 0}
```

Вопросы появятся с эталонными ответами у открытых. Учебная реализация может быть синхронной: `200` + созданные вопросы.

## 5. Вопросы и варианты (teacher) — не реализовано (план)

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/tests/{test_id}/questions` | вопросы теста по `order_index` |
| `POST` | `/tests/{test_id}/questions` | добавить вопрос (с вариантами или эталоном) |
| `PATCH` | `/questions/{question_id}` | изменить `text`, `points`, `order_index` |
| `DELETE` | `/questions/{question_id}` | удалить вопрос |
| `PUT` | `/tests/{test_id}/questions/order` | переставить порядок |

`POST /tests/{test_id}/questions` — закрытый вопрос:

```json
{
  "type": "closed",
  "text": "Что такое первичный ключ?",
  "points": 1,
  "options": [
    {"text": "Уникальный идентификатор строки", "is_correct": true, "order_index": 1},
    {"text": "Индекс таблицы", "is_correct": false, "order_index": 2}
  ]
}
```

Открытый вопрос:

```json
{
  "type": "open",
  "text": "Объясните разницу между INNER и LEFT JOIN",
  "points": 3,
  "reference_answer": "INNER возвращает только совпадения, LEFT — все строки левой таблицы..."
}
```

`201` — вопрос с `id`, `order_index` (если не передан — в конец).

Правила: у `closed` минимум 2 варианта и ровно один `is_correct`; у `open` непустой `reference_answer`. Иначе `400`.

`PUT /tests/{test_id}/questions/order`:

```json
{"question_ids": ["<id1>", "<id2>", "<id3>"]}
```

## 7. Прохождение теста (student) — не реализовано (план)

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/assignments/{assignment_id}/start` | начать попытку → создать `result` |
| `GET` | `/results/{result_id}` | состояние попытки, свои ответы |
| `PUT` | `/results/{result_id}/answers/{question_id}` | сохранить ответ (идемпотентно) |
| `POST` | `/results/{result_id}/submit` | завершить попытку и запустить автопроверку |

`POST /assignments/{assignment_id}/start` — идемпотентно: если попытка уже есть и не завершена, возвращается она (`200` вместо `201`). `403`, если назначение чужое; `400`, если тест не опубликован или попытка уже сдана.

`201`:

```json
{"id": "...", "assignment_id": "...", "test_version": 1, "status": "in_progress", "auto_score": null, "final_score": null}
```

`GET /results/{result_id}` — тест с вопросами **без `is_correct`** и без правильных ответов, плюс сохранённые ответы. Флаг правильности раскрывается только после проверки.

```json
{
  "id": "...",
  "status": "in_progress",
  "questions": [
    {"id": "...", "type": "closed", "text": "...", "points": 1, "order_index": 1,
     "options": [{"id": "...", "text": "...", "order_index": 1}]},
    {"id": "...", "type": "open", "text": "...", "points": 3, "order_index": 2}
  ],
  "answers": [
    {"question_id": "...", "selected_option_id": "..."}
  ]
}
```

`PUT /results/{result_id}/answers/{question_id}` — закрытый вопрос:

```json
{"selected_option_id": "..."}
```

открытый:

```json
{"answer_text": "INNER JOIN возвращает только совпавшие строки..."}
```

`200` — сохранённый ответ. `400`, если тип ответа не соответствует типу вопроса; `409`, если попытка уже сдана. Уникальность `(result_id, question_id)` — один ответ на вопрос, повторный `PUT` перезаписывает.

`POST /results/{result_id}/submit` — `200`:

```json
{"id": "...", "status": "auto_checked", "auto_score": 6.0, "final_score": null}
```

Логика: закрытые вопросы проверяются сразу (`is_correct_auto`, сумма в `auto_score`). Если открытых вопросов нет — `status: "graded"` и `final_score = auto_score`. Если есть — `status: "auto_checked"`, ждёт преподавателя.

## 8. Проверка (teacher)

### `POST /answers/check` — реализовано

Проверяет список ответов по эталону: на каждый элемент списка — один запрос к GigaChat, вердикт
`is_correct` возвращается в том же порядке. Эндпоинт stateless: результаты проверки не сохраняются.

```json
{
  "answers": [
    {"question_id": "...", "question": "Столица Франции?", "correct_answer": "Париж", "user_answer": "Париж"}
  ]
}
```

`200` — тот же список с добавленным `is_correct`:

```json
{
  "answers": [
    {"question_id": "...", "question": "Столица Франции?", "correct_answer": "Париж", "user_answer": "Париж", "is_correct": true}
  ]
}
```

Список непустой и не длиннее 20 элементов; `question` и `correct_answer` — непустые строки,
`question_id` — UUID, `user_answer` может быть пустым. Ошибки: `401` — нет или неверен токен; `403` —
роль не `teacher`; `422` — невалидный список; `502` — GigaChat недоступен или вернул невалидный
вердикт.

### Остальные операции проверки — не реализовано (план)

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/results?test_id=&assignment_id=&status=&limit=&offset=` | результаты по своим тестам |
| `GET` | `/results/{result_id}/answers` | ответы для проверки (с правильными вариантами) |
| `PATCH` | `/answers/{answer_id}` | оценка и комментарий преподавателя |
| `POST` | `/results/{result_id}/grade` | зафиксировать итог |

`PATCH /answers/{answer_id}`:

```json
{"teacher_score": 2.0, "teacher_comment": "Не хватает примера"}
```

`200` — ответ с `teacher_score`, `teacher_comment`, `llm_score`, `llm_feedback`.

`POST /results/{result_id}/grade` — `200`:

```json
{"id": "...", "status": "graded", "auto_score": 6.0, "final_score": 8.0, "graded_by": "...", "graded_at": "2026-11-24T11:00:00Z"}
```

Считает `final_score = auto_score + сумма(teacher_score)` и переводит назначение в `graded`. `400`, если не все открытые ответы оценены.

## Что отложено

- **JWT** — сейчас токен-заглушка: `access_token` равен `id` пользователя, подписи и срока действия нет.
- **Список и карточка пользователей** (`/users`) — не реализовано.
- **CRUD тестов и вопросов, назначения, прохождение, проверка** — описаны как план; реализовано
  только создание теста по материалу (`POST /materials/{material_id}/tests`).
- **`GET /health`** — не реализовано.
- **LLM** — генерация теста и проверка одного ответа (`POST /answers/check`) работают; сохранения
  результатов проверки и пакетной проверки ещё нет.
- **Фоновая генерация** — создание теста синхронное: запрос держится до ответа модели (таймаут 60 с),
  статуса `generating` и очереди нет.
- **Версионирование теста** (`test_version` в результатах) — пока константа `1`.
- **Миграции** — пока `create_all`; при изменении моделей БД пересоздаётся через
  `testlab-init-db --reset`.
- **Очистка «осиротевших» файлов** — файл удаляется best-effort после коммита; фоновая уборка не
  реализована.
