# Proposal

## Why

Сейчас преподаватель может только загрузить материал и создать по нему тест: управлять тестом после
создания нельзя — его не видно в отдельном списке, нельзя переименовать, опубликовать, отправить в
архив, удалить или перегенерировать вопросы. Тест живёт только как вложенный объект карточки
материала, а `docs/API.md` описывает эти операции как план. Без них сценарий «сгенерировал → поправил →
опубликовал» не собирается, а тест, опубликованный один раз, невозможно ни исправить, ни убрать.
Заодно в текущем правиле есть тупик: архивный тест навсегда блокирует создание нового теста по тому
же материалу (`409`), а удалить его нельзя.

## What Changes

- **Новые эндпоинты жизненного цикла теста** под `/tests`:
  - `GET /tests?material_id=&status=&limit=&offset=` — список своих тестов с пагинацией и фильтрами;
  - `GET /tests/{test_id}` — тест с вопросами, вариантами и рубриками;
  - `PATCH /tests/{test_id}` — изменить `title` (только `draft`);
  - `POST /tests/{test_id}/publish` — `draft` → `published`, `400` если вопросов нет;
  - `POST /tests/{test_id}/archive` — `published` → `archived`;
  - `DELETE /tests/{test_id}` — удалить тест в любом статусе;
  - `POST /tests/{test_id}/generate` — перегенерировать вопросы черновика через LLM.
- **Правило неизменяемости**: после публикации тест нельзя менять — ни `title`, ни вопросы, ни
  перегенерация; доступны только архив и удаление.
- **Перегенерация заменяет вопросы черновика целиком**; отдельного подтверждения (`?force`) нет —
  черновик и так управляется преподавателем.
- **Ослабляется правило `409`** у `POST /materials/{material_id}/tests`: новый тест запрещён, только
  если у материала уже есть тест в статусе `draft` или `published`; архивный тест считается историей
  и не блокирует создание следующего.
- **`TestOut` дополняется** полями `material_id` и `created_at` — без них список, карточка и
  результаты действий нечего показывать (эти поля уже обещаны в примерах `docs/API.md`).
- **Удаление теста разрешено в любом статусе**: `archived` защищает не данные, а только сценарий
  использования — сданных работ и назначений в системе пока нет, поэтому запрет удаления ничего бы не
  защитил, зато заставлял бы удалять материал вместе с PDF.
- `docs/API.md`: раздел «Остальные операции с тестами — не реализовано (план)» переписывается как
  реализованный контракт.

## Capabilities

### New Capabilities

- `tests-lifecycle`: управление тестом как самостоятельным объектом — список и карточка теста,
  изменение черновика, публикация, архивирование, удаление, перегенерация вопросов и правило
  неизменяемости опубликованного теста.

### Modified Capabilities

- `materials`: меняются два требования — `Повторная генерация теста отклоняется` (архивный тест больше
  не блокирует создание нового) и `Карточка материала` (отдаёт последний тест по `created_at` и
  `test: null`, когда тестов нет).

## Impact

- `src/testlab/routers/test.py` — второй роутер `prefix="/tests"` (список, карточка, `PATCH`,
  `publish`, `archive`, `DELETE`, `generate`); регистрация в `src/testlab/__main__.py`.
- `src/testlab/services/test.py` — use cases `list_tests`, `get_test`, `update_title`, `publish`,
  `archive`, `delete_test`, `regenerate`; общие хелперы генерации с `generate_for_material`.
- `src/testlab/repositories/test.py` — выборка по владельцу, список с фильтрами и `total`, выборка
  активного теста по материалу, удаление.
- `src/testlab/schemas/test.py` — `TestSummaryOut`, `TestListOut`, `TestUpdateRequest`; сюда
  переезжают `TestOut`, `QuestionOut`, `ClosedOptionOut`, `RubricOut` из `schemas/material.py`.
- `src/testlab/errors.py` — `EmptyTestError` → `400` (публикация без вопросов).
- `docs/API.md` — раздел 4; `tests/api/`, `tests/services/`, `tests/repositories/` — новые сценарии.
- Схема БД и зависимости не меняются: `tests.status` и `questions.source` уже есть, миграций нет.
