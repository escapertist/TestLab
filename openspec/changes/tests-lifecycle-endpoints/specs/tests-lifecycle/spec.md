# Spec Delta

## Purpose

Описывает жизненный цикл теста как самостоятельного объекта: просмотр, изменение черновика, публикация, архивирование, удаление и перегенерация вопросов, а также правило неизменяемости опубликованного теста.

## ADDED Requirements

### Requirement: Тестами управляет только преподаватель
Все операции над тестами SHALL требовать роль `teacher`: пользователь с ролью `student` получает `403`, запрос без заголовка `Authorization` или с неизвестным токеном — `401`.

#### Scenario: Роль не преподаватель
- **WHEN** любой эндпоинт `/tests` вызывает пользователь с ролью `student`
- **THEN** ответ `403`

#### Scenario: Нет или неверен токен
- **WHEN** запрос к `/tests` приходит без заголовка `Authorization` или с неизвестным идентификатором
- **THEN** ответ `401`

### Requirement: Список своих тестов
`GET /tests?limit=&offset=` SHALL возвращать `{"items": [Test, ...], "total": N}` только для тестов текущего преподавателя, отсортированных по `created_at` по убыванию, затем по `id` по убыванию. `limit` по умолчанию 20, допустимый диапазон 1..100; `offset` не меньше 0; значение вне диапазона — `422`.

#### Scenario: Пагинация
- **WHEN** у преподавателя 25 тестов и запрошен `limit=10&offset=20`
- **THEN** ответ `200` содержит 5 последних по `created_at` элементов и `total=25`

#### Scenario: Чужие тесты не попадают в список
- **WHEN** тесты есть у двух преподавателей
- **THEN** каждый видит только свои тесты, `total` считает только свои

#### Scenario: Пустой список
- **WHEN** у преподавателя нет тестов
- **THEN** ответ `200` содержит `items: []` и `total=0`

#### Scenario: Невалидные параметры пагинации
- **WHEN** `limit=0`, `limit=101` или `offset=-1`
- **THEN** ответ `422`

#### Scenario: Элемент списка без вопросов
- **WHEN** клиент получает список тестов
- **THEN** элемент содержит `id`, `material_id`, `title`, `status`, `created_at` и не содержит `questions`

### Requirement: Фильтры списка тестов
`GET /tests` SHALL поддерживать необязательные фильтры `material_id` и `status`: `material_id` ограничивает выборку тестами этого материала, `status` — тестами в этом статусе, вместе — их пересечением. `total` считает отфильтрованное количество.

#### Scenario: Фильтр по материалу
- **WHEN** запрошен `GET /tests?material_id=<id>`
- **THEN** ответ содержит только тесты этого материала, `total` считает только их

#### Scenario: Фильтр по статусу
- **WHEN** запрошен `GET /tests?status=published`
- **THEN** ответ содержит только опубликованные тесты

#### Scenario: Оба фильтра
- **WHEN** запрошены `material_id` и `status` одновременно
- **THEN** ответ содержит тесты этого материала в этом статусе

#### Scenario: Неизвестный статус в фильтре
- **WHEN** в `status` передано значение вне `draft`, `published`, `archived`
- **THEN** ответ `422`

#### Scenario: Материал без тестов
- **WHEN** запрошен фильтр по материалу, у которого тестов нет
- **THEN** ответ `200` содержит `items: []` и `total=0`

### Requirement: Тест отдаётся с вопросами
`GET /tests/{test_id}` SHALL возвращать `200` с тестом: `id`, `material_id`, `title`, `status`, `generation_params`, `created_at` и `questions` в порядке `order_index`, с вариантами у закрытых вопросов и рубриками у открытых.

#### Scenario: Карточка своего теста
- **WHEN** преподаватель запрашивает свой тест
- **THEN** ответ `200` содержит тест со всеми вопросами, вариантами и рубриками

#### Scenario: Порядок вопросов
- **WHEN** у теста вопросы с `order_index` по порядку
- **THEN** `questions` в ответе идут в порядке `order_index`

### Requirement: Изменение названия черновика
`PATCH /tests/{test_id}` SHALL принимать только `title` (1..255 символов) и применять изменение только к тесту в статусе `draft`; для `published` и `archived` — `409`. `generation_params` телом запроса SHALL NOT изменяться: это метаданные генерации, их пересчитывает сервис.

#### Scenario: Изменение названия черновика
- **WHEN** преподаватель отправляет `{"title": "Новое название"}` для своего черновика
- **THEN** ответ `200` с новым названием
- **AND** статус остаётся `draft`

#### Scenario: Название опубликованного теста
- **WHEN** `PATCH` применён к тесту в статусе `published` или `archived`
- **THEN** ответ `409`, название не меняется

#### Scenario: Поля кроме названия
- **WHEN** тело запроса содержит `generation_params` или не содержит `title`
- **THEN** ответ `422`

#### Scenario: Пустое название
- **WHEN** `title` — пустая строка или длиннее 255 символов
- **THEN** ответ `422`

### Requirement: Публикация теста
`POST /tests/{test_id}/publish` SHALL переводить тест из `draft` в `published` и возвращать `200` с тестом; из `published` или `archived` — `409`. Обратный переход `published` → `draft` не существует.

#### Scenario: Публикация черновика
- **WHEN** преподаватель публикует свой черновик, в котором есть вопросы
- **THEN** ответ `200`, `status` теста — `published`
- **AND** список с фильтром `status=published` содержит этот тест

#### Scenario: Повторная публикация
- **WHEN** тест уже `published` или `archived`
- **THEN** ответ `409`, статус не меняется

### Requirement: Публикация требует вопросов
`POST /tests/{test_id}/publish` SHALL возвращать `400`, не меняя статус, если у черновика нет ни одного вопроса.

#### Scenario: Публикация теста без вопросов
- **WHEN** у черновика нет вопросов
- **THEN** ответ `400`, статус остаётся `draft`

### Requirement: Архивирование теста
`POST /tests/{test_id}/archive` SHALL переводить тест из `published` в `archived` и возвращать `200` с тестом; для `draft` и `archived` — `409`.

#### Scenario: Архивирование опубликованного теста
- **WHEN** преподаватель архивирует свой опубликованный тест
- **THEN** ответ `200`, `status` — `archived`

#### Scenario: Архивирование черновика
- **WHEN** архив запрошен для теста в статусе `draft` или уже `archived`
- **THEN** ответ `409`, статус не меняется

### Requirement: Опубликованный тест не изменяется
После перехода в `published` тест SHALL NOT меняться: `PATCH`, изменение вопросов и перегенерация отвечают `409`, пока тест не удалён или не отправлен в архив. Изменить опубликованный тест можно только удалением или архивированием.

#### Scenario: Изменение опубликованного теста
- **WHEN** вызваны `PATCH`, `POST /tests/{test_id}/generate` или изменение вопросов для `published`
- **THEN** ответ `409`, вопросы и название не меняются

#### Scenario: Архивный тест тоже неизменяем
- **WHEN** те же операции вызваны для `archived`
- **THEN** ответ `409`

### Requirement: Удаление теста
`DELETE /tests/{test_id}` SHALL возвращать `204` и удалять тест с вопросами, вариантами и рубриками в любом статусе; материал и его файл не затрагиваются. После удаления карточка материала отдаёт `test: null`, а создание нового теста по материалу снова доступно.

#### Scenario: Удаление теста в любом статусе
- **WHEN** преподаватель удаляет свой тест в статусе `draft`, `published` или `archived`
- **THEN** ответ `204` без тела
- **AND** тест, его вопросы, варианты и рубрики недоступны после запроса

#### Scenario: Материал остаётся
- **WHEN** тест удалён
- **THEN** материал и его файл по-прежнему доступны, карточка отдаёт `test: null`
- **AND** `POST /materials/{material_id}/tests` снова создаёт тест

#### Scenario: Повторное удаление
- **WHEN** тест уже удалён
- **THEN** ответ `404`

### Requirement: Перегенерация вопросов черновика
`POST /tests/{test_id}/generate` SHALL заменять все вопросы теста целиком результатом новой генерации и возвращать `200` с тестом: прежние вопросы удаляются, новые получают `order_index` по порядку, `generation_params` пересчитываются, `title` не меняется. Для теста не в статусе `draft` — `409`.

#### Scenario: Перегенерация черновика
- **WHEN** преподаватель перегенерирует свой черновик
- **THEN** ответ `200` содержит новые вопросы в составе из `generation_params`
- **AND** идентификаторы прежних вопросов в ответе отсутствуют

#### Scenario: Название не меняется
- **WHEN** у черновика изменённое название `title`, после чего вызвана перегенерация
- **THEN** `title` остаётся прежним, `generation_params` пересчитаны

#### Scenario: Перегенерация опубликованного теста
- **WHEN** перегенерация запрошена для `published` или `archived`
- **THEN** ответ `409`, вопросы не меняются

#### Scenario: Файл материала потерян
- **WHEN** записи материала нет или файла по сохранённому пути нет
- **THEN** ответ `404`, вопросы не меняются

### Requirement: Сбой модели при перегенерации сохраняет тест
Если модель недоступна или её ответ нарушает контракт, `POST /tests/{test_id}/generate` SHALL возвращать `502`, оставляя прежние вопросы, `generation_params` и статус без изменений.

#### Scenario: Модель вернула некорректный ответ
- **WHEN** генерация при перегенерации завершилась ошибкой модели
- **THEN** ответ `502`
- **AND** тест остаётся `draft` с прежними вопросами и прежним `generation_params`

### Requirement: Чужой тест неотличим от отсутствующего
Для теста другого преподавателя список, карточка, `PATCH`, публикация, архивирование, удаление и перегенерация SHALL возвращать `404`, а не `403`, чтобы не раскрывать существование объекта.

#### Scenario: Карточка чужого теста
- **WHEN** преподаватель запрашивает тест другого преподавателя
- **THEN** ответ `404`

#### Scenario: Изменение чужого теста
- **WHEN** преподаватель вызывает `PATCH`, `publish`, `archive`, `generate` или `DELETE` для чужого теста
- **THEN** ответ `404`
- **AND** тест остаётся без изменений
