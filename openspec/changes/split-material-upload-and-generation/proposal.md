# Proposal

## Why

Сейчас `POST /materials` одновременно сохраняет файл и генерирует тест: ответ приходит только после вызова GigaChat (до 60 с), а сбой модели выглядит как провал загрузки (`502`). Из-за этого не видно, что сам файл в порядке, перегенерировать тест без повторной загрузки нельзя, а фронтенд не может отличить «материал принят» от «материал и тест готовы».

## What Changes

- **`POST /materials` — только загрузка.** Проверяет PDF (тип, размер, наличие текстового слоя), сохраняет файл и запись материала, отвечает `201` с материалом. **BREAKING**: из ответа исчезает поле `test`; вызов LLM из этого запроса убирается.
- **Новый `POST /materials/{material_id}/tests` — отдельное действие «создать тест».** Читает сохранённый файл, извлекает текст, вызывает GigaChat, создаёт тест `draft` с 7 вопросами и возвращает `201` с `TestOut`. Ничего не сохраняет при неуспехе.
- **Идемпотентность по материалу**: если у материала уже есть тест, ответ `409`; повторный клик по кнопке не создаёт второй тест.
- **Разделение сервисов**: `MaterialService` перестаёт зависеть от LLM-клиента; генерация переносится в новый `TestService`; файл читается через `FileStorage.read`, а не напрямую с диска.
- **Новая доменная ошибка `ConflictError`** → `409` в централизованном маппинге.
- **Карточка материала** уже отдаёт `test: null` — состояние «файл загружен, тест ещё не создан» становится штатным, интерфейс может показать кнопку генерации.
- **Документация**: `docs/API.md` — новый контракт загрузки, новое действие, коды `201/400/404/409/502`, обновлённый порядок реализации.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `materials`: загрузка материала больше не создаёт тест; добавляется отдельное действие создания теста по материалу с `409` при повторе и `502` при сбое модели.
- `llm-test-generation`: сбой генерации относится к действию создания теста (тест не сохраняется), а не к загрузке материала; сама загрузка ошибок модели больше не порождает.

## Impact

- Код: `routers/material.py`, новый `routers/test.py`, `services/material.py`, новый `services/test.py`, новый `dependencies/test.py`, `infrastructure/storage.py` (метод чтения), `errors.py` (`ConflictError`), `schemas/material.py` (ответ загрузки без теста), `tests/`.
- HTTP: **BREAKING** — ответ `POST /materials` больше не содержит `test`; добавлен `POST /materials/{material_id}/tests`.
- Данные: схема БД не меняется; тест создаётся со статусом `draft` и вопросами, как сейчас.
- Зависимости: без изменений (`pypdf`, `httpx` уже есть).
- Документация: `docs/API.md`; при необходимости `AGENTS.md` (состав сервисов и роутеров).
- Последовательность архивации: базовые спецификации `materials` и `llm-test-generation` пока живут в незаархивированном `refactor-layering-materials-crud`, поэтому его нужно архивировать до этого change, иначе дельты `MODIFIED` не с чем слить.
