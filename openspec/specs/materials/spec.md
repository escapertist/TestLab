# materials Specification

## Purpose

Описывает работу преподавателя с учебными материалами: загрузку PDF с автоматической генерацией теста, список материалов с пагинацией, карточку, скачивание файла и удаление материала вместе со связанными данными.

## Requirements

### Requirement: Загрузка материала запускает генерацию теста
Преподаватель SHALL загружать учебный материал через `POST /materials` (multipart: `file` — PDF, `title`) и получать `201` с созданным материалом и сгенерированным тестом. Материал сохраняется с владельцем из токена, файл — в каталог загрузок, тест создаётся в статусе `draft` с вопросами.

#### Scenario: Успешная загрузка
- **WHEN** преподаватель отправляет PDF с текстовым слоем и непустой `title`
- **THEN** ответ `201` содержит материал (`id`, `title`, `filename`, `is_uploaded`, `created_at`) и вложенный тест со статусом `draft` и вопросами
- **AND** материал принадлежит преподавателю из токена, файл сохранён в каталог загрузок

#### Scenario: Загружен не PDF
- **WHEN** расширение файла не `.pdf` или `Content-Type` не `application/pdf`
- **THEN** ответ `400` с сообщением, что нужен PDF-файл
- **AND** материал, тест и файл не создаются

#### Scenario: Пустой файл
- **WHEN** тело загруженного файла имеет нулевой размер
- **THEN** ответ `400`

#### Scenario: Файл больше лимита
- **WHEN** размер файла превышает лимит загрузки (по умолчанию 10 МБ)
- **THEN** ответ `413`
- **AND** файл не записывается на диск и материал не создаётся

#### Scenario: В PDF нет текстового слоя
- **WHEN** из PDF не извлекается ни одного символа текста
- **THEN** ответ `400` с сообщением, что PDF не содержит текстового слоя
- **AND** файл не сохраняется, генерация не запускается

#### Scenario: Роль не преподаватель
- **WHEN** `POST /materials` вызывает пользователь с ролью `student`
- **THEN** ответ `403`

#### Scenario: Нет или неверен токен
- **WHEN** запрос приходит без заголовка `Authorization` или с неизвестным идентификатором
- **THEN** ответ `401`

### Requirement: Сбой генерации не оставляет данных
Если генерация теста завершилась ошибкой (`LLMError`), сервис SHALL вернуть `502` с текстом ошибки и не сохранять ни материал, ни тест, ни файл.

#### Scenario: GigaChat вернул некорректный ответ
- **WHEN** модель вернула не JSON, пустой список вопросов или нарушила состав теста
- **THEN** ответ `502`
- **AND** в базе нет ни материала, ни теста, в каталоге загрузок нет файла

### Requirement: Сбой сохранения не оставляет частичных данных
Если запись материала или теста в базу завершилась ошибкой, сервис SHALL вернуть `500`, откатить транзакцию и удалить уже записанный файл; материал без теста не сохраняется.

#### Scenario: Ошибка записи теста после записи материала
- **WHEN** сохранение теста с вопросами завершается ошибкой БД
- **THEN** ответ `500`
- **AND** материал, тест и файл отсутствуют после запроса

### Requirement: Список своих материалов с пагинацией
`GET /materials?limit=&offset=` SHALL возвращать `{"items": [Material, ...], "total": N}` только для материалов текущего преподавателя, отсортированных по `created_at` по убыванию. `limit` по умолчанию 20, допустимый диапазон 1..100; `offset` не меньше 0; значение вне диапазона — `422`.

#### Scenario: Пагинация
- **WHEN** у преподавателя 25 материалов и запрошен `limit=10&offset=20`
- **THEN** ответ `200` содержит 5 последних по `created_at` элементов и `total=25`

#### Scenario: Чужие материалы не попадают в список
- **WHEN** материалы есть у двух преподавателей
- **THEN** каждый видит только свои материалы, `total` считает только свои

#### Scenario: Невалидные параметры пагинации
- **WHEN** `limit=0`, `limit=101` или `offset=-1`
- **THEN** ответ `422`

### Requirement: Карточка материала
`GET /materials/{material_id}` SHALL возвращать `200` с полями материала и вложенным тестом (с вопросами, вариантами и рубриками), если тест был сгенерирован.

#### Scenario: Карточка своего материала
- **WHEN** преподаватель запрашивает существующий свой материал
- **THEN** ответ `200` содержит материал и его тест с вопросами

#### Scenario: Серверный путь к файлу не раскрывается
- **WHEN** клиент получает карточку, список или результат загрузки
- **THEN** ни один ответ не содержит `file_path` и другие серверные пути

### Requirement: Скачивание файла материала
`GET /materials/{material_id}/file` SHALL возвращать `200` с `Content-Type: application/pdf` и исходным именем файла в `Content-Disposition`. Если файл отсутствует на диске — `404`.

#### Scenario: Скачивание файла
- **WHEN** преподаватель запрашивает файл своего материала
- **THEN** ответ `200` отдаёт содержимое PDF с исходным именем файла

#### Scenario: Файл потерян на диске
- **WHEN** запись материала есть, а файла по сохранённому пути нет
- **THEN** ответ `404`

### Requirement: Удаление материала
`DELETE /materials/{material_id}` SHALL возвращать `204` и удалять материал, его файл на диске и связанные тесты с вопросами, вариантами и рубриками. Отсутствие файла на диске не мешает удалению.

#### Scenario: Удаление своего материала
- **WHEN** преподаватель удаляет свой материал
- **THEN** ответ `204` без тела
- **AND** материал, его тесты и файл недоступны после запроса

#### Scenario: Повторное удаление
- **WHEN** материал уже удалён
- **THEN** ответ `404`

#### Scenario: Файл уже отсутствует
- **WHEN** запись материала есть, а файла на диске нет
- **THEN** ответ `204`, запись материала и связанные тесты удалены

### Requirement: Чужой материал неотличим от отсутствующего
Для материала другого преподавателя все операции чтения, скачивания и удаления SHALL возвращать `404`, а не `403`, чтобы не раскрывать существование объекта.

#### Scenario: Карточка чужого материала
- **WHEN** преподаватель запрашивает материал, принадлежащий другому преподавателю
- **THEN** ответ `404`

#### Scenario: Удаление чужого материала
- **WHEN** преподаватель удаляет материал другого преподавателя
- **THEN** ответ `404`
- **AND** материал остаётся без изменений
