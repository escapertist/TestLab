# materials Specification

## Purpose

Описывает работу преподавателя с учебными материалами: загрузку PDF с автоматической генерацией теста, список материалов с пагинацией, карточку, скачивание файла и удаление материала вместе со связанными данными.

## Requirements

### Requirement: Загрузка материала сохраняет файл
Преподаватель SHALL загружать материал через `POST /materials` (multipart: `file` — PDF, `title`) и получать `201` с сохранённым материалом. Запрос SHALL проверять тип файла, размер и наличие текстового слоя, сохранять файл в каталог загрузок и запись материала с владельцем из токена. Тест при загрузке не создаётся, поля `test` в ответе нет.

#### Scenario: Успешная загрузка
- **WHEN** преподаватель отправляет PDF с текстовым слоем и непустой `title`
- **THEN** ответ `201` содержит материал (`id`, `title`, `filename`, `is_uploaded`, `created_at`) и не содержит `test`
- **AND** файл сохранён в каталог загрузок, материал принадлежит преподавателю из токена

#### Scenario: Загружен не PDF
- **WHEN** расширение файла не `.pdf` или `Content-Type` не `application/pdf`
- **THEN** ответ `400` с сообщением, что нужен PDF-файл
- **AND** материал и файл не создаются

#### Scenario: Пустой файл
- **WHEN** тело загруженного файла имеет нулевой размер
- **THEN** ответ `400`

#### Scenario: Файл больше лимита
- **WHEN** размер файла превышает лимит загрузки (по умолчанию 10 МБ)
- **THEN** ответ `413`
- **AND** файл не записывается на диск и материал не создаётся

#### Scenario: В PDF нет текстового слоя
- **WHEN** из PDF не извлекается ни одного символа текста
- **THEN** ответ `400` с сообщением, что PDF не содержит текстового слоя
- **AND** файл не сохраняется и материал не создаётся

#### Scenario: Роль не преподаватель
- **WHEN** `POST /materials` вызывает пользователь с ролью `student`
- **THEN** ответ `403`

#### Scenario: Нет или неверен токен
- **WHEN** запрос приходит без заголовка `Authorization` или с неизвестным идентификатором
- **THEN** ответ `401`

### Requirement: Тест создаётся отдельным действием
`POST /materials/{material_id}/tests` SHALL читать сохранённый файл материала, извлекать текст, генерировать тест по нему и сохранять тест в статусе `draft` с вопросами, возвращая `201` с созданным тестом. Тело запроса необязательно; если передан `title`, он используется как название теста.

#### Scenario: Тест создаётся по сохранённому файлу
- **WHEN** преподаватель вызывает действие для своего материала, у которого ещё нет теста
- **THEN** ответ `201` содержит тест с 7 вопросами, вариантами и рубриками
- **AND** карточка материала после этого отдаёт этот тест

#### Scenario: Название теста из запроса
- **WHEN** в теле передано `{"title": "Итоговый тест"}`
- **THEN** созданный тест имеет это название
- **AND** без тела название берётся из ответа модели

#### Scenario: Файл материала потерян на диске
- **WHEN** запись материала есть, а файла по сохранённому пути нет
- **THEN** ответ `404`, тест не создаётся

#### Scenario: Роль не преподаватель
- **WHEN** действие вызывает пользователь с ролью `student`
- **THEN** ответ `403`

### Requirement: Повторная генерация теста отклоняется
Если у материала уже есть тест, `POST /materials/{material_id}/tests` SHALL возвращать `409` и не создавать второй тест.

#### Scenario: Повторный вызов действия
- **WHEN** преподаватель повторно вызывает создание теста для материала, у которого тест уже есть
- **THEN** ответ `409`
- **AND** в карточке остаётся прежний тест, новые вопросы не появляются

### Requirement: Сбой генерации не оставляет теста
Если модель недоступна или её ответ нарушает контракт, действие создания теста SHALL вернуть `502`, не сохраняя тест и вопросы. Загруженный материал и файл при этом остаются доступны.

#### Scenario: Модель вернула некорректный ответ
- **WHEN** на создании теста модель недоступна или нарушила контракт
- **THEN** ответ `502`
- **AND** карточка материала отдаёт `test: null`, файл материала по-прежнему скачивается

### Requirement: Сбой сохранения не оставляет частичных данных
Если запись материала в базу завершилась ошибкой, сервис SHALL вернуть `500`, откатить транзакцию и удалить уже записанный файл. Если ошибкой завершилась запись теста, сервис SHALL вернуть `500` и не сохранять ни тест, ни вопросы.

#### Scenario: Ошибка записи материала после записи файла
- **WHEN** сохранение материала завершается ошибкой БД
- **THEN** ответ `500`
- **AND** материал и файл отсутствуют после запроса

#### Scenario: Ошибка записи теста после записи материала
- **WHEN** сохранение теста с вопросами завершается ошибкой БД
- **THEN** ответ `500`
- **AND** теста и вопросов нет, материал остаётся загруженным

### Requirement: Список своих материалов с пагинацией
`GET /materials?limit=&offset=` SHALL возвращать `{"items": [Material, ...], "total": N}` только для материалов текущего преподавателя, отсортированных по `created_at` по убыванию. `limit` по умолчанию 20, допустимый диапазон 1..100; `offset` не меньше 0; значение вне диапазона — `422`.

#### Scenario: Пагинация
- **WHEN** у преподавателя 25 материалов и запрошен `limit=10&offset=20`
- **THEN** ответ `200` содержит 5 последних по `created_at` элементов и `total=25`

#### Scenario: Чужие материалы не попадают в список
- **WHEN** материалы есть у двух преподавателей
- **THEN** каждый видит только свои материалы, `total` считает только свои

#### Scenario: Невалидные параметры пагинации
- **WHEN** `limit=0`, `limit=101` или `offset=-1`
- **THEN** ответ `422`

### Requirement: Карточка материала
`GET /materials/{material_id}` SHALL возвращать `200` с полями материала и вложенным тестом (с вопросами, вариантами и рубриками), если тест создан, либо `test: null`, если тест ещё не создавался.

#### Scenario: Карточка своего материала
- **WHEN** преподаватель запрашивает существующий свой материал, по которому тест создан
- **THEN** ответ `200` содержит материал и его тест с вопросами

#### Scenario: Карточка материала без теста
- **WHEN** преподаватель запрашивает свой материал, по которому тест ещё не создавали
- **THEN** ответ `200` содержит `test: null`
- **AND** файл материала при этом скачивается

#### Scenario: Серверный путь к файлу не раскрывается
- **WHEN** клиент получает карточку, список или результат загрузки
- **THEN** ни один ответ не содержит `file_path` и другие серверные пути

### Requirement: Скачивание файла материала
`GET /materials/{material_id}/file` SHALL возвращать `200` с `Content-Type: application/pdf` и исходным именем файла в `Content-Disposition`. Если файл отсутствует на диске — `404`.

#### Scenario: Скачивание файла
- **WHEN** преподаватель запрашивает файл своего материала
- **THEN** ответ `200` отдаёт содержимое PDF с исходным именем файла

#### Scenario: Файл потерян на диске
- **WHEN** запись материала есть, а файла по сохранённому пути нет
- **THEN** ответ `404`

### Requirement: Удаление материала
`DELETE /materials/{material_id}` SHALL возвращать `204` и удалять материал, его файл на диске и связанные тесты с вопросами, вариантами и рубриками. Отсутствие файла на диске не мешает удалению.

#### Scenario: Удаление своего материала
- **WHEN** преподаватель удаляет свой материал
- **THEN** ответ `204` без тела
- **AND** материал, его тесты и файл недоступны после запроса

#### Scenario: Повторное удаление
- **WHEN** материал уже удалён
- **THEN** ответ `404`

#### Scenario: Файл уже отсутствует
- **WHEN** запись материала есть, а файла на диске нет
- **THEN** ответ `204`, запись материала и связанные тесты удалены

### Requirement: Чужой материал неотличим от отсутствующего
Для материала другого преподавателя все операции чтения, скачивания, создания теста и удаления SHALL возвращать `404`, а не `403`, чтобы не раскрывать существование объекта.

#### Scenario: Карточка чужого материала
- **WHEN** преподаватель запрашивает материал, принадлежащий другому преподавателю
- **THEN** ответ `404`

#### Scenario: Создание теста для чужого материала
- **WHEN** преподаватель вызывает создание теста для материала другого преподавателя
- **THEN** ответ `404`
- **AND** тест не создаётся

#### Scenario: Удаление чужого материала
- **WHEN** преподаватель удаляет материал другого преподавателя
- **THEN** ответ `404`
- **AND** материал остаётся без изменений
