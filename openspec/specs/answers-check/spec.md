# answers-check Specification

## Purpose

Позволяет преподавателю проверить ответы учащегося: сервис отправляет каждый ответ в модель и возвращает список с вердиктом `is_correct`.

## Requirements

### Requirement: Проверка ответов доступна только преподавателю
`POST /answers/check` SHALL требовать роль `teacher`: пользователь с ролью `student` получает `403`, запрос без заголовка `Authorization` или с неизвестным токеном — `401`.

#### Scenario: Роль не преподаватель
- **WHEN** эндпоинт `/answers/check` вызывает пользователь с ролью `student`
- **THEN** ответ `403`

#### Scenario: Нет или неверен токен
- **WHEN** запрос приходит без заголовка `Authorization` или с неизвестным идентификатором
- **THEN** ответ `401`

### Requirement: Проверка списка ответов
`POST /answers/check` SHALL принимать `{"answers": [...]}`, где каждый элемент содержит `question_id`, `question`, `correct_answer` и `user_answer`, и возвращать `200` с тем же списком в исходном порядке, где у каждого элемента добавлено поле `is_correct`.

#### Scenario: Проверка списка
- **WHEN** преподаватель отправляет список ответов
- **THEN** ответ `200` содержит те же элементы в том же порядке с полем `is_correct: true` или `false`

#### Scenario: Невалидный список
- **WHEN** список пуст, содержит больше 20 элементов или в элементе отсутствует/пусто одно из полей `question_id`, `question`, `correct_answer`, `user_answer`
- **THEN** ответ `422`

### Requirement: Один запрос в модель на один ответ
Для каждого элемента списка сервис SHALL выполнять ровно один вызов модели, передавая в промпт `question`, `correct_answer` и `user_answer` (без `question_id`), а вердикт `is_correct` SHALL возвращаться моделью в структурированном виде.

#### Scenario: Ошибка в одном ответе не мешает остальным
- **WHEN** проверяется список из нескольких ответов
- **THEN** каждый элемент проверяется независимо, вердикт вычисляется отдельно для каждого

### Requirement: Сбой модели при проверке
Если модель недоступна или её ответ не проходит валидацию схемы, `POST /answers/check` SHALL возвращать `502`.

#### Scenario: Модель недоступна
- **WHEN** запрос к модели завершился ошибкой сети или авторизации
- **THEN** ответ `502`

#### Scenario: Ответ модели вне схемы
- **WHEN** модель вернула вердикт не в виде `is_correct: true/false`
- **THEN** ответ `502`
